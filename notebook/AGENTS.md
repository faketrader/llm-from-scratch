# AGENTS.md

## 课程定位

课程名称：**大模型：从原理实现到生产实践**。

目标：面向已经具备 Python、张量、损失函数、梯度下降和基本神经网络概念的读者，编写循序渐进的 Jupyter Notebook 教程。每章以最小数据和必要抽象从零实现核心机制，再用可观察证据验证，最后迁移到生产中实际使用的 PyTorch、Transformers、Datasets、TRL、PEFT、Diffusers 等主流库与工程契约。

本课程不是完整零基础课程。`10_foundations.ipynb` 只负责快速恢复共同语言，不能把所有前置知识压缩进该章。

## 共同基础与三条方向

- 共同基础围绕数据、分词、模型前向计算、自回归生成与基本评估建立语言；完整数学推导和训练实践随专项学习加深。
- 应用智能体系统：上下文与提示、RAG、工具、工作流与智能体；Harness 属于执行与控制的深入专题。
- 模型训练方法：数据、监督微调和参数高效适配；预训练、偏好对齐和推理训练按目标深入。
- 训练推理系统：资源预算之后分别进入训练系统与推理服务；模型优化按机制补齐相应前置。
- 数据、评估、安全、模型家族与多模态作为共通方法或跨方向专题。

README 与各 Notebook 学习契约必须明确方向、知识前置、资产条件和学习终点。方向通过主题与文件组合形成；主题选读不代表任意单元格可以跳序执行。既有等价知识可以满足知识前置，实际输入仍须满足资产契约。不得将预训练、后训练或全套部署实验设为应用方向的统一入门门槛。

第三方开放权重模型作为评测对象或部署制品时，`E10_open_model.ipynb` 的模型仓库审计是条件性前置；评测、部署和安全验收引用同一份 Model Audit Manifest。服务发布仍须通过相应评估与安全保障。

## 固定章节结构

每个 Notebook 必须使用以下结构，名称和顺序保持一致：

1. `学习契约`：路线、章节定位、先修知识、预计时间、运行资源、交付物。
2. `直觉与输入输出契约`：回答为什么现在学习、输入是什么、输出是什么、形状如何变化。
3. `最小原理实现`：只实现揭示核心原理所需的最小闭环，不用高级 API 隐藏过程。
4. `证据验证`：使用形状、数值、梯度、因果性、重载一致性、指标或失败案例验证。
5. `迁移到生产库`：切换到主流库，给出原理实现对象与库对象的一一映射；库不是另一份无关代码。
6. `生产边界`：说明版本、性能、恢复、安全、扩展与维护边界。

现有章节可以在统一书挡之间保留更细的主题小节，但必须保留上述六个一级章节。Notebook 以“生产边界”结束，不再设置独立的练习、作业或交付章节；必要的验证条件应融入“证据验证”或“生产边界”。每个关键步骤都要说明做什么、输入、输出、为什么这样设计以及如何验证。

## 写作语言

- 中文为主；必要英文术语首次出现时给出英文全称和中文含义。
- 先用直觉和具体问题引入，再给公式、代码和工程术语。
- 避免连续堆叠缩写；同一段出现多个新术语时，先给关系图或对照表。
- 生产风险集中放在“生产边界”，不要用大量“必须、不得、不要”打断核心原理主线。
- 标题准确描述完成范围，不能用“完整实现”指代只覆盖若干核心组件的最小原理实现。
- 章节编号使用阿拉伯数字和全角点号，例如 `## 3．证据验证`；小节使用 `### 3.1．形状检查`。

### 成文与编辑指令的边界

- 正文采用正式、清晰、自然的书面语，避免“先看”“不要猜”“到底”“究竟”“真正终点”“够用”“跑通”“好看”等口语化或情绪化措辞。
- 正文统一使用“从零实现”“原理实现”或“最小实现”，不使用“手搓”“手写”等口语化表述。
- 不以“你会”“你应该”等第二人称直接要求读者；学习目标使用“完成本章后，读者能够……”或客观陈述。
- 写给作者或编辑助手的要求只保留在本文件，不得复制到 Notebook、README 或附录正文。正文不得出现编辑过程、提示词、对助手的命令，或“为了符合要求而加入”等元叙述。
- 约束性措辞仅用于确有风险的技术边界；一般原理说明优先陈述因果关系、适用条件和后果，避免连续使用“必须、不得、不要”。

## 原理实现、验证与库迁移

- 原理实现函数使用 `my_` 前缀，原理实现类使用 `My` 前缀；变量、参数、属性和常量遵循 Python 与框架惯例。
- 先完成最小原理实现，再与库实现比较；不一开始使用高级 API 掩盖核心过程。
- 验证必须产生学习证据。不要使用无解释的 `assert`；输入契约错误可抛出明确异常，数值与行为等价性应打印或可视化关键结果。
- 库迁移至少说明：概念映射、输入输出映射、默认值差异、保存加载方式和生产中不再保留哪些原理代码。
- 系统类章节没有单一对应库时，先从零实现最小控制环、状态机、容量模型或数据契约，再迁移到生产组件边界和标准接口。

## 公式到函数与库

- 每个关键公式都必须给出符号表和张量形状，指出公式中的对象在代码里对应哪个参数、张量或维度。
- 公式之后先给最小原理实现函数，再给生产库函数或类，形成“公式 → 原理实现函数 → 库 API → 生产 Kernel/Runtime”的连续映射。
- 至少验证数值、形状或梯度中的一项；涉及 Mask、Reduction、Padding、广播、归一化、精度或随机采样时，必须说明库默认值差异。
- 库内部使用 fused kernel、编译或近似算法时，要区分“数学语义保持不变”和“数值/性能实现发生变化”。
- 没有对应单一库函数的系统公式，应映射到容量模型、Schema 校验、调度器或评测指标，不能只停留在 LaTeX。

## Notebook 要求

- 每个 Notebook 必须独立运行，不依赖其他 Notebook 的内存、变量或执行顺序。
- 独立运行使用最小输入或按资产 ID 直接加载上游当前文件；Hub 调用不传 `revision`，Manifest 也不记录上游 Revision。下载后的文件仍计算内容哈希；同时允许消费上游章节交付的版本化文件。
- 章节之间传递 Checkpoint、Adapter、Manifest、Tokenizer、配置和评测报告，不传递 Notebook 内存状态。
- 关键代码添加简洁中文注释，重点说明数据流、张量形状、算法原因和验证证据，不逐行复述。
- 矩阵或高阶张量的具体维度如果能由字面量、固定样例或当前配置静态确定，必须在定义处相邻标注，例如 `weight.shape = [512, 13]`，并在容易混淆时注明轴语义。`nn.Linear(in_features, out_features)` 的权重按 PyTorch 存储顺序标为 `[out_features, in_features]`。只有运行时才能确定的维度继续使用 `[N,L,E]`、`[B,H,T,S]` 等符号，不得虚构具体数字；reshape 中的 `-1` 也不得写成未经推导的固定维度。
- 只解释影响数据、模型、训练、推理、评测或复现契约的关键数值：协议常量注明来源，数据固有值注明契约，实验缩放值注明缩小理由，超参数注明典型范围与调整影响。说明应写在相应代码或配置首次定义处的相邻中文注释中；公式常量、索引、单位换算、打印行数与图形尺寸无需添加注释，除非它们会改变算法语义或验收结果。
- 公式使用 Jupyter/Colab MathJax LaTeX；模型、模块、张量、组件拓扑等架构图统一使用 TikZ 源文件，并由 `scripts/render_tikz_diagrams.py` 编译为自包含 SVG 供 Notebook 显示。TikZ 图必须保留 `.tex` 源文件、使用共享样式、标注关键形状，并通过 XeLaTeX 与 dvisvgm 静态构建；不得用 `\boxed` / `array` 公式冒充架构图。过程流程、状态机、生命周期与时序图使用 Mermaid。
- 每章至少提供整体流程图和核心模块关系图；其中核心模块关系图使用 TikZ，复杂训练、推理或部署链路的过程流、状态转换或时序图使用 Mermaid。
- 在使用依赖的地方再导入，不在开头集中导入全部依赖。
- 修改 Notebook 后不得自动运行 Notebook、项目代码、训练、推理或测试；只有用户明确要求时才执行。
- Notebook 可以不保存执行输出，但 Markdown 必须给出预期形状、数值范围、行为或可视化判据，让读者能够判断是否运行正确。
- 预计超过 3 秒或处理规模随数据、步数、文件大小增长的操作必须提供实时进度反馈。自定义循环统一使用 `tqdm.auto`，至少显示阶段、完成量、总量、速率和预计剩余时间；训练与评估还应显示当前 Loss、学习率或关键指标。Hugging Face Trainer、Datasets、Hub 下载与 Diffusers 等已有原生进度条的库接口不得关闭进度显示，也不得再套重复进度条。多阶段任务必须在切换下载、校验、预处理、训练、评估、保存或重载时更新阶段名称；若底层编译或设备初始化 API 不暴露可度量总量，则显示明确阶段与持续时间，不伪造百分比或 ETA。异常退出时不得伪装成 100% 完成。

## 可视化证据

课程中的图分为四类，职责不可混用：TikZ 负责模型、模块、张量和组件拓扑架构，并编译为 SVG；Mermaid 负责过程、职责流、状态机、生命周期与时序；Matplotlib 负责真实张量、概率、矩阵、曲线、轨迹和权衡关系；`ipywidgets` 只用于少数需要反事实探索的参数，并且必须同时提供无需 Widget 的静态视图。不得将 XY-pic、Plotly、自定义 JavaScript 或依赖联网前端资源的图形作为核心学习路径。

每章至少选择一个最抽象、最容易误解或最需要数值证据的核心机制，提供由本章真实原理实现或真实实验记录生成的机制可视化。系统类章节没有单一张量时，使用容量、队列、状态、风险、成本、延迟或质量数据生成运行证据图。既有整体流程图和核心模块关系图不能替代机制可视化。

每个机制可视化必须形成以下闭环：

1. 明确它回答的学习问题和对应输入、输出或 Trace。
2. 直接消费正文的 `my_*` 原理函数、真实中间张量或真实实验记录，不另写一套只为绘图服务的算法，不手填理想化结果。
3. 在绘图前验证至少一个可证伪的不变量，例如 Attention 行和、Mask 后概率、Next-token 移位、概率归一化、Label Mask、Cache 一致性或置信区间计算口径。
4. 提供确定性的 Matplotlib 静态视图；交互仅作为增强，并使用同一份已缓存的小型 Trace，不在控件变化时重新训练模型。
5. 图后说明应观察到的现象、失败意味着什么，以及该图不能推出的结论。
6. 同时给出数值摘要、表格或文字等价信息，关键信息不能只由颜色、动画或 Hover 表达。

可视化张量在呈现前统一沿 `detach() → float() → cpu()` 路径转换，避免保留计算图或 GPU/MPS 引用。长序列、大词表和多层多头结果必须显式切片、聚合或选择代表状态，并写明切片规则；不得把不可读的大矩阵直接压缩成像素图。颜色应采用色觉友好色板，标题、轴、单位、Token、Layer、Head、Mask 语义和色条必须完整，状态差异同时使用数值、边界、标记或线型表达。

以下误读边界必须就地说明：Attention 权重不是严格的因果解释；Embedding、Hidden State 或 Reward 的二维投影存在失真；单次 Next-token 采样或单条生成路径不能代表完整概率分布或模型质量；漂亮的训练曲线不能替代固定验证集、统计不确定性与失败切片。

优先可视化的机制包括但不限于：BPE 合并与 Token 边界、位置编码与 RoPE、Attention 与 Mask、残差与归一化、Next-token 移位与采样、Token Loss 与梯度、SFT/DPO/GRPO 信号、LoRA 低秩增量、评测置信区间与 Pareto 前沿、KV Cache 与连续批处理、并行训练与显存状态、量化和压缩误差、RAG 证据链、ViT/多模态 Token 流、Diffusion/Flow 轨迹、Verifier 与 Test-time Compute，以及部署与安全控制的运行证据。

## 数值、超参数与随机性

- Notebook 不设置独立的“本章数值说明”段落或汇总表。`HYPERPARAMETERS.md` 只提供跨章节方法论，不能替代相应代码或配置附近的具体注释。
- 关键数值在相应代码常量、配置字段或函数参数首次定义处就地说明作用、单位、选择依据、调整影响与复核条件；不得把多项说明集中复制为与实现脱节的顶部注释块。
- 每个关键数字必须先分类为数学/协议常量、数据固有值、实验缩放值、模型结构参数、训练/推理/系统超参数或随机种子，不能把所有数字统称为超参数。
- 每个可调值至少说明：控制对象与单位、当前选择依据、调大/调小影响、耦合参数、失效条件、重调指标和生产记录项。只写“常见值”“经验值”或“参考默认值”不算完成解释。
- 实验缩放值必须说明其为何足以验证机制，以及为何不能直接迁移到生产；协议值必须注明来源和需要同步的消费者；数据值必须绑定数据或制品契约。
- 学习率必须结合训练制度、有效 Token Batch、优化器、warmup 和训练预算解释；batch 必须区分 micro-batch、梯度累积、设备数、全局样本数与全局有效 Token 数。
- `num_train_epochs` 与 `max_steps`、warmup steps 与 ratio、LoRA `alpha` 与 `rank`、hidden size 与 head 数、Tokenizer 与 vocabulary/context、生成参数与 sampling 开关等覆盖或耦合关系必须就地写清。
- seed 是实验控制条件，不是质量超参数。课程单次默认值统一为：`E40_cv_vit.ipynb`、`E50_cv_diffusion.ipynb` 使用 `3407`，其余章节使用 `42`；年份不得再充当默认 seed。多 Seed 评测保留预先登记的不同整数集合，不得搜索或挑选最好看的 seed。
- 质量结论使用多个 seed，报告均值和离散程度；同时记录数据划分、初始化、采样/解码所用的 seed。固定 seed 不得表述为跨框架版本、平台、CPU/GPU 或 Kernel 的完全确定性保证。
- 最终超参数必须随模型 ID、数据版本、代码版本、关键文件哈希、硬件、精度、搜索空间、选择指标和验收结果写入 Manifest。

## Transformer 边界

- `30_transformer.ipynb` 以《Attention Is All You Need》为主线，只讲论文核心的 Encoder–Decoder：Embedding、正弦位置编码、Scaled Dot-Product Attention、Mask、Multi-Head Attention、FFN、残差、LayerNorm、Encoder、Decoder、Cross-Attention、Teacher Forcing 与自回归翻译。
- 本章从原理实现过渡到 `torch.nn.Transformer`，通过形状、数值与因果性对齐建立生产库坐标。
- Decoder-only、GPT Block、Causal LM、生成接口、KV Cache、RoPE、GQA 和现代 GPT 家族差异只在 `31_nlp_gpt.ipynb` 讲解，不在 Transformer 章重复。
- MoE 属于架构进阶知识，只在与训练或推理系统边界相关的位置建立地图，不插入 Transformer 论文核心主线。

## 开放权重模型与推理模型边界

- `E10_open_model.ipynb` 以 Qwen、DeepSeek、Kimi、GLM、MiniMax，以及 Llama、Gemma、Phi、gpt-oss、Nemotron 为主要样本：审计仓库文件、Config、Tokenizer、Chat Template、Safetensors、Adapter、量化制品和自定义代码，从 GPT 基线识别架构增量，并形成 Model Audit Manifest 与服务验收矩阵。
- 该章必须区分 Open Source、Open Weights 与 API-only，并分别记录权重/代码许可证、使用政策和衍生条款；不得把“权重可下载”直接等同于 OSI 意义的开源或自由商用。
- 该章区分稳定正文、带日期的当前快照、Preview 和 Experimental；型号、上下文长度、许可证和 Kernel 支持不得写成长期不变的结论，也不做排行榜式推荐。
- 各家族的完整网络不得在模型专题中重复实现；MoE 并行、推理优化与推理训练分别回链对应系统或训练专题。
- DeepSeek-R1-Distill-Qwen 属于 Qwen 网络架构上的蒸馏 Checkpoint，不能用于证明 DeepSeek MLA 或 DeepSeekMoE。
- `A30_reasoning_model.ipynb` 统一讲 Reasoning-trace SFT、ORM/PRM、RLVR、验证后蒸馏与 Test-Time Compute；不得把 CoT 表达成独立网络层或统一损失。
- 原始推理轨迹、可验证证据和面向用户的解释必须分开。默认不把原始 CoT 当作审计日志或普通 API 返回。

## 多模态模型边界

- `E20_multimodal_llm.ipynb` 建立多模态全景，并以 Vision-Language Model 的视觉编码器、Projector/Resampler、序列与 Label Mask 作为最小原理实现主线；图像/视频生成只讲任务、架构与选型坐标。
- `E50_cv_diffusion.ipynb` 负责生成视觉原理与生产迁移：潜空间扩散、条件 U-Net、Diffusion Transformer、Flow Matching、VAE、文生图和文生视频；不得在 `E20` 重复实现去噪器。
- 模型图谱以中国和美国公开权重家族为主，可以加入少量欧洲等国际参照。图像理解、视频理解、图像生成、图像编辑、视频生成和世界模型必须分列，不能用“多模态”混成一个能力标签。
- 生产验收必须固定 Processor/Tokenizer/VAE/Scheduler/Chat Template 等完整制品，分别评测事实正确性、提示遵循、时序一致性、性能、安全、版权与许可证。

## 应用章节边界

- `90_llm_applications.ipynb` 保持为一个 Notebook，用“模型上线助手”完成 RAG → 一个只读 Tool → 固定 Workflow / ReAct Agent → 带引用生成 → 基础评测。
- RAG 主线只讲文档、切块、单路 BM25、Top-k/阈值、证据包、Recall@K 和无答案拒绝；Embedding、混合检索、Reranker 与索引平台只列为后续扩展，不写生产实现。
- Agent 主线只讲“Decision → Action → Observation → 继续或结束”的基本循环，并对比四步固定 Workflow 与最小 ReAct 风格循环；ReAct 只记录公开决策摘要，不展示原始 CoT。保留输入 Schema、步骤/工具次数和基础 Trace，不实现平台治理代码。
- 联网和 MCP 不进入本章内容。
- 已知步骤优先固定 Workflow；步骤无法事先确定时才考虑 ReAct。模型不能新增工具、放宽预算或直接执行副作用。
- 应用内容不得再拆成多个重复的 RAG、Tool Calling 或 Agent Notebook。

## 模型评估边界

- `50_model_evaluation.ipynb` 负责把“模型看起来不错”变成可审计证据：冻结任务与风险目标、版本化样本和切片、实现确定性指标、校准生成式评审、报告统计不确定性，并形成部署准入门禁与后续在线实验协议。
- 必须区分模型评估、系统评估和业务实验。困惑度、Accuracy、Exact Match、偏好胜率、Judge 分数、延迟、成本和业务指标回答不同问题，不得压成一个总分。
- LLM-as-a-Judge 只能作为经人工金标校准的测量工具；必须固定 Judge 模型/Prompt/解码配置，检查位置、长度、风格和自偏好偏差，并保留人工升级路径。
- 方案比较优先使用成对样本与置信区间；多 Seed、切片、鲁棒性、安全和无答案场景必须保留。发布门槛来自冻结基线、风险容忍与统计证据，不能照抄示例阈值。
- 在线实验必须先通过离线硬门禁，再采用可回滚灰度；同时评估质量、延迟、成本、安全和用户影响，不得只追逐单一互动率。

## 大规模数据工程边界

- `20_dataset.ipynb` 保持单机数据资产、JSONL、Schema、划分与 Hugging Face Datasets 基础闭环；LLM 数据集谱系和异构格式分类统一由 `A20_data_engineering.ipynb` 负责。
- `A20_data_engineering.ipynb` 必须区分物理格式、样本 Schema、消费用途与学习目标、内容属性、模态、治理与血缘六个维度。JSONL、Alpaca、对话和 CoT 不得并列为同层类型。
- Alpaca、ShareGPT、OpenAI Messages 等生态格式只作为入口 Schema；生产内部采用公共 Envelope 与按 `sample_type` 判别的类型化 Payload，并保留原始记录、Schema Version、Adapter Revision 和内容哈希。
- 未知或歧义 Schema 不得根据字段静默猜测，必须隔离并记录稳定原因码。会话、偏好对、工具轨迹、问题家族与多模态媒体保持原子边界完成去重、划分、物化和 Sharding。
- CoT 属于内容与监督粒度，原始推理轨迹、最终答案和验证证据分别治理；推理轨迹的训练与 Verifier 细节仍由 `A30_reasoning_model.ipynb` 负责。

## 路线与文件

- 共同基础的机制实践：`10 → 20 → 21 → 30 → 31`。
- 应用智能体系统：`50 → 91 → 90`，提前阅读 `70` 的威胁模型与工具授权；发布时衔接 `60`、`70`。
- 模型训练方法：训练知识 → `41` 的 SFT → `42`；预训练专题 `40`，数据专题 `A20`，对齐与推理专题 `41 → A30`。
- 训练推理系统：资源基础 `A10`；推理服务 `50 → 60 → 70 → A50`；训练系统 `40 → A40`；模型优化专题 `A60`。
- 共通方法：`50` 评估、`70` 安全；跨方向专题：`E10`、`E20`、`E30`、`E40`、`E50`。

详细依赖以 README 与学习契约为准。文件前缀作为稳定标识保留，方向和层次通过学习契约表达；新增文件使用唯一主题标识，避免因路线组合复制内容。

## 运行环境与依赖

- 支持 Apple Silicon 与 Google Colab。
- 设备选择统一使用 `torch.accelerator.current_accelerator(check_available=True) or torch.device("cpu")`；CUDA 专属能力根据 `device.type` 判断。
- 依赖版本以 最新 Colab https://github.com/googlecolab/backend-info 为准；Notebook 中不自行维护另一套冲突版本。
- 优先使用小模型、小数据和可直观理解的例子；扩大规模时进入对应方向的深入专题。

## 生产资产边界

- 预训练输出可恢复 Checkpoint；后训练输出策略 Checkpoint 或绑定基座模型 ID 与权重哈希的 Adapter。
- PEFT 减少可训练参数，不等于模型压缩。
- 模型压缩输出带格式、校准和目标 Kernel 元数据的制品。
- 资源规划输出可校准容量模型；大规模数据工程输出不可变 Dataset Contract、Schema/Adapter Revision、Manifest 与 Shard。
- 推理模型工程输出绑定 Dataset、Verifier、Parser、Reward、Template 和服务预算的策略制品。
- 模型评估输出绑定 Dataset、Slice、Metric、Judge、生成配置、统计方法、基线与门禁决策的不可变评测报告。
- 应用绑定模型、检索配置、Prompt 与 Tool Schema 版本。
- 所有生产资产必须具有来源、版本、哈希、评测证据和回滚路径。
